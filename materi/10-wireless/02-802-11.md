## 1. Generasi Wi-Fi

| Standar | Nama pemasaran | Tahun | Band | Kecepatan maks (PHY) | Fitur kunci |
|---|---|---|---|---|---|
| 802.11 | — | 1997 | 2,4 | 2 Mbps | Asli |
| 802.11b | — | 1999 | 2,4 | 11 Mbps | DSSS |
| 802.11a | — | 1999 | 5 | 54 Mbps | OFDM |
| 802.11g | — | 2003 | 2,4 | 54 Mbps | OFDM di 2,4 |
| **802.11n** | **Wi-Fi 4** | 2009 | 2,4 + 5 | 600 Mbps | **MIMO**, 40 MHz, frame aggregation |
| **802.11ac** | **Wi-Fi 5** | 2013 | 5 | 6,9 Gbps | 80/160 MHz, 256-QAM, **MU-MIMO (DL)** |
| **802.11ax** | **Wi-Fi 6** | 2019 | 2,4 + 5 | 9,6 Gbps | **OFDMA**, 1024-QAM, BSS coloring, TWT |

⚠️ **Angka kecepatan itu adalah PHY rate teoretis maksimum** — dicapai hanya dalam kondisi laboratorium dengan jumlah spatial stream maksimum, kanal terlebar, modulasi tertinggi, dan satu klien. **Throughput nyata biasanya 40–60% dari angka itu**, dan terbagi antar-semua klien.

### Amandemen penting lainnya

```
802.11i  → keamanan (WPA2)
802.11e  → QoS (WMM)
802.11k  → radio resource measurement (bantu roaming)
802.11r  → fast BSS transition (fast roaming)
802.11v  → wireless network management (steering klien)
802.11w  → protected management frames (anti-deauth)
802.11h  → DFS & TPC
802.11s  → mesh networking
802.11ah → HaLow (900 MHz, IoT jarak jauh)
802.11ad/ay → WiGig (60 GHz, jarak sangat pendek, kecepatan sangat tinggi)
```

💡 **802.11k/v/r adalah trio roaming** — dukungan ketiganya membuat perpindahan antar-AP mulus. Sangat penting untuk VoIP dan perangkat bergerak.

## 2. CSMA/CA — Akses Media Nirkabel

Wi-Fi tidak bisa memakai CSMA/CD (Collision Detection) karena **radio tidak dapat mendengar saat mengirim** — sinyal kirimnya sendiri jutaan kali lebih kuat daripada yang diterima.

Solusinya: **CSMA/CA** (Collision **Avoidance**).

```
1. Perangkat ingin mengirim
2. CARRIER SENSE — dengarkan kanal
   ├── Physical CS  : deteksi energi RF
   └── Virtual CS   : NAV (Network Allocation Vector) dari frame lain
3. Kanal sibuk? → TUNGGU sampai sepi
4. Kanal sepi? → tunggu DIFS (Distributed InterFrame Space)
5. Pilih backoff ACAK dari contention window
6. Hitung mundur; berhenti kalau kanal jadi sibuk
7. Backoff = 0 → KIRIM
8. Tunggu ACK. Tidak ada ACK? → anggap tabrakan, gandakan CW, ulangi
```

### InterFrame Space

```
SIFS  (Short)       : terpendek — untuk ACK, CTS (prioritas tertinggi)
PIFS                : untuk PCF (jarang dipakai)
DIFS  (Distributed) : untuk data biasa
AIFS                : DIFS yang bervariasi per kelas QoS (WMM)
```

Perangkat yang menunggu **lebih singkat** mendapat prioritas — inilah dasar QoS wireless.

### Setiap frame data WAJIB di-ACK

```
Pengirim → DATA → Penerima
Pengirim ← ACK  ← Penerima
```

⚠️ **Ini berarti setiap transmisi data memakan DUA kali airtime.** Tidak seperti Ethernet yang mengandalkan TCP untuk keandalan, Wi-Fi melakukan ACK di **layer 2**. Karena media nirkabel jauh lebih tidak andal, retransmisi di L2 jauh lebih efisien daripada menunggu TCP timeout.

### RTS/CTS dan Hidden Node

```
Masalah hidden node:
  [A] ←──→ [AP] ←──→ [B]
   A dan B TIDAK saling mendengar (terhalang dinding)
   → keduanya mengira kanal sepi
   → keduanya mengirim → TABRAKAN di AP
```

**Solusi RTS/CTS:**
```
A → RTS (Request To Send) → AP
AP → CTS (Clear To Send) → SEMUA (termasuk B)
B mendengar CTS → set NAV → DIAM selama durasi yang disebutkan
A mengirim data dengan aman
```

⚠️ **RTS/CTS menambah overhead besar.** Aktifkan hanya kalau memang ada masalah hidden node. Ambang default (`rts-threshold`) biasanya diset sangat tinggi sehingga praktis nonaktif.

## 3. Kenapa Throughput Nyata Jauh Lebih Rendah

Ini pertanyaan yang paling sering diajukan pengguna.

```
Klaim: "Wi-Fi 6 sampai 9,6 Gbps!"
Nyata: 300–800 Mbps untuk satu klien di kondisi baik
```

**Penyebabnya berlapis:**

| Faktor | Dampak |
|---|---|
| **Half duplex** | Kirim dan terima bergantian → kapasitas efektif terbagi |
| **Overhead protokol** | Preamble, header, ACK, IFS, backoff → 40–50% airtime |
| **CSMA/CA contention** | Makin banyak klien, makin banyak waktu menunggu |
| **Rate adaptation** | Klien jauh memakai MCS rendah |
| **Airtime fairness** | Satu klien lambat memakan airtime tidak proporsional |
| **Retransmisi** | Setiap frame yang gagal harus diulang |
| **Beacon & management** | AP mengirim beacon 10×/detik per SSID |
| **Co-channel interference** | AP tetangga di kanal sama berbagi airtime |

### Masalah "klien lambat menyeret semua"

```
Klien A (dekat AP)  : MCS 11, 1000 Mbps → 1 MB butuh 8 ms airtime
Klien B (jauh)      : MCS 0,  6 Mbps    → 1 MB butuh 1333 ms airtime

Kalau keduanya mengunduh 1 MB:
  Tanpa airtime fairness → B memakan 99% airtime
  → A ikut lambat, padahal sinyalnya sempurna
```

💡 **Airtime fairness** (fitur di AP enterprise) mengalokasikan **waktu**, bukan jumlah paket — sehingga klien lambat tidak menghambat yang cepat.

⚠️ **Perangkat 802.11b/g lama sangat merusak.** Satu klien 802.11b di jaringan modern memaksa AP memakai **protection mechanism** (RTS/CTS atau CTS-to-self) yang menurunkan throughput seluruh sel hingga 50–80%.

```
# Matikan rate rendah agar perangkat sangat lama tidak bisa terhubung
# MikroTik
/interface wireless set wlan1 basic-rates-b="" supported-rates-b="" \
    basic-rates-a/g=12Mbps supported-rates-a/g=12Mbps,18Mbps,24Mbps,36Mbps,48Mbps,54Mbps
```

## 4. Frame 802.11

Berbeda dari Ethernet, frame 802.11 punya **hingga 4 alamat MAC**.

```
┌──────────┬────────┬──────┬──────┬──────┬──────┬──────┬─────────┬─────┐
│ Frame    │Duration│ Addr │ Addr │ Addr │ Seq  │ Addr │ Payload │ FCS │
│ Control  │ /ID    │  1   │  2   │  3   │ Ctrl │  4   │         │     │
│ 2 byte   │ 2 byte │6 byte│6 byte│6 byte│2 byte│6 byte│         │4byte│
└──────────┴────────┴──────┴──────┴──────┴──────┴──────┴─────────┴─────┘
```

**Kenapa 4 alamat?** Karena frame bisa melewati AP:
```
Klien → AP → jaringan kabel:
  Addr1 = BSSID (MAC AP)      ← penerima langsung
  Addr2 = MAC klien           ← pengirim
  Addr3 = MAC tujuan akhir
  Addr4 = (dipakai hanya di mode WDS/mesh)
```

### Tiga jenis frame

**Management frames** — mengelola koneksi:
```
Beacon           → AP mengumumkan diri (10×/detik per SSID)
Probe Request    → klien mencari AP
Probe Response   → AP menjawab
Authentication   → autentikasi 802.11 (bukan keamanan sesungguhnya)
Association Req/Resp → bergabung ke AP
Reassociation    → pindah AP (roaming)
Disassociation   → keluar
Deauthentication → dipaksa keluar  ⚠️ dipakai untuk serangan
Action           → 802.11k/v, block ack, dll
```

**Control frames** — mengatur akses media:
```
RTS / CTS        → reservasi media
ACK              → konfirmasi penerimaan
Block ACK        → konfirmasi banyak frame sekaligus (efisien)
PS-Poll          → klien power save meminta data tersimpan
```

**Data frames** — membawa payload.

⚠️ **Management dan control frame TIDAK terenkripsi** pada WPA2 biasa. Inilah yang memungkinkan **serangan deauthentication** — penyerang mengirim frame deauth palsu untuk memutus klien.

💡 **802.11w (Protected Management Frames / PMF)** mengenkripsi management frame dan mencegah serangan ini. **WAJIB pada WPA3**, opsional pada WPA2.

```
# MikroTik — aktifkan PMF
/interface wireless security-profiles set default management-protection=allowed
   # allowed | required
```

## 5. Proses Koneksi Klien

```
1. SCANNING
   ├── Passive : dengarkan beacon di setiap kanal
   └── Active  : kirim Probe Request, tunggu Probe Response

2. AUTHENTICATION (802.11 — bukan keamanan!)
   Open System: klien minta, AP setuju
   (Shared Key sudah usang dan tidak aman)

3. ASSOCIATION
   Klien → Association Request (kemampuan, SSID, rate yang didukung)
   AP    → Association Response (AID = Association ID)

4. AUTENTIKASI SESUNGGUHNYA
   ├── PSK      : 4-way handshake WPA2/WPA3
   └── 802.1X   : EAP + RADIUS

5. DHCP → alamat IP

6. SIAP ✅
```

⚠️ **"Authentication" di langkah 2 bukan keamanan.** Ia warisan dari standar asli dan selalu berhasil. Keamanan sesungguhnya ada di langkah 4.

### Hidden SSID — kenapa tidak berguna

```
AP tidak menyiarkan SSID di beacon.

Tetapi SSID tetap muncul dalam plaintext di:
  - Probe Request dari klien yang mencarinya
  - Probe Response
  - Association Request
```

⚠️ **Hidden SSID memberi rasa aman yang palsu.** Alat seperti `airodump-ng` menemukannya dalam hitungan detik. Efek sampingnya justru buruk:
- Klien harus **aktif mengirim probe** berisi nama SSID → **membocorkan** jaringan yang biasa Anda kunjungi ke mana pun Anda pergi
- Beberapa perangkat kesulitan terhubung atau lambat roaming
- Menyulitkan troubleshooting

💡 **Jangan sembunyikan SSID.** Gunakan WPA3/WPA2 yang kuat dan 802.1X sebagai keamanan sesungguhnya.

## 6. MIMO dan Spatial Stream

**MIMO** (*Multiple Input Multiple Output*) memakai beberapa antena untuk mengirim **beberapa aliran data secara bersamaan** di frekuensi yang sama.

```
Notasi: TxR:S
  T = jumlah antena pemancar
  R = jumlah antena penerima
  S = jumlah spatial stream

2x2:2  → 2 antena, 2 stream
3x3:3  → 3 antena, 3 stream
4x4:4  → 4 antena, 4 stream (umum di AP enterprise)
8x8:8  → maksimum standar
```

⚠️ **Kecepatan dibatasi oleh sisi dengan stream paling sedikit.** AP 4x4:4 dengan ponsel 2x2:2 → hanya 2 stream yang dipakai. Kebanyakan ponsel adalah 2x2, laptop 2x2 atau 3x3.

### Jenis MIMO

| Jenis | Cara kerja |
|---|---|
| **SU-MIMO** | Beberapa stream ke **satu** klien (802.11n) |
| **MU-MIMO** | Beberapa stream ke **beberapa klien bersamaan** (802.11ac DL, 802.11ax DL+UL) |
| **Beamforming** | Memfokuskan energi ke arah klien tertentu |
| **MRC** | Menggabungkan sinyal dari beberapa antena untuk memperbaiki penerimaan |

💡 **MU-MIMO membutuhkan klien yang mendukungnya dan kondisi RF yang baik.** Dalam praktik, manfaatnya sering lebih kecil daripada yang diiklankan. **OFDMA (Wi-Fi 6) memberi peningkatan yang jauh lebih konsisten.**

## 7. Wi-Fi 6 (802.11ax) — Perubahan Paradigma

Wi-Fi 6 bukan sekadar "lebih cepat" — ia dirancang untuk **efisiensi di lingkungan padat**.

### OFDMA — perubahan terbesar

```
SEBELUM (Wi-Fi 5): satu transmisi = satu klien
  ┌────────────────────────────────┐
  │      Klien A (seluruh kanal)   │  waktu 1
  ├────────────────────────────────┤
  │      Klien B (seluruh kanal)   │  waktu 2
  └────────────────────────────────┘

WI-FI 6 (OFDMA): satu transmisi = BEBERAPA klien
  ┌──────┬──────┬──────┬──────────┐
  │  A   │  B   │  C   │    D     │  waktu 1
  └──────┴──────┴──────┴──────────┘
   ← Resource Unit (RU) →
```

Kanal dibagi menjadi **Resource Unit (RU)** yang dialokasikan ke klien berbeda secara bersamaan.

💡 **Manfaat terbesar untuk paket kecil dan banyak perangkat** — IoT, ponsel, sensor. Sebelumnya, mengirim paket 100 byte memakan seluruh kanal selama satu slot waktu; dengan OFDMA, puluhan paket kecil dikirim bersamaan.

### Fitur Wi-Fi 6 lainnya

| Fitur | Manfaat |
|---|---|
| **1024-QAM** | +25% kecepatan (butuh SNR sangat tinggi) |
| **BSS Coloring** | Membedakan sel yang tumpang tindih → mengurangi penundaan tidak perlu |
| **TWT** (Target Wake Time) | Perangkat IoT tidur lebih lama → baterai jauh lebih awet |
| **UL MU-MIMO** | Beberapa klien mengirim ke AP bersamaan |
| **Longer OFDM symbol** | Lebih tahan interferensi outdoor |
| **WPA3 wajib** untuk sertifikasi Wi-Fi 6 | Keamanan lebih baik |

**BSS Coloring** memecahkan masalah nyata:
```
Tanpa coloring: AP mendengar transmisi dari sel tetangga di kanal yang sama
                → menunda pengiriman meski sebenarnya tidak akan bertabrakan
Dengan coloring: setiap BSS punya "warna"; transmisi dari warna berbeda
                dengan sinyal lemah bisa DIABAIKAN → lebih banyak transmisi paralel
```

## 8. Wi-Fi 7 (802.11be)

| Fitur | Penjelasan |
|---|---|
| **MLO** (Multi-Link Operation) | **Fitur terpenting** — satu koneksi logis memakai **beberapa band sekaligus** (2,4+5+6 GHz) |
| **320 MHz** | Kanal dua kali lebih lebar (hanya di 6 GHz) |
| **4096-QAM** | +20% kecepatan (butuh SNR ~40+ dB) |
| **Multi-RU** | Satu klien bisa memakai beberapa RU tidak berdekatan |
| **16 spatial stream** | Dua kali lipat Wi-Fi 6 |

### MLO — mengapa penting

```
Sebelum: klien memilih SATU band, terikat sampai roaming
MLO    : klien terhubung ke 5 GHz DAN 6 GHz sekaligus

Manfaat:
  - Agregasi throughput (jumlahkan kapasitas kedua band)
  - Redundansi (satu band terganggu, yang lain lanjut)
  - Latency lebih rendah dan LEBIH KONSISTEN
  - Perpindahan band tanpa memutus koneksi
```

💡 **MLO memberi manfaat paling nyata bukan pada kecepatan puncak, melainkan pada konsistensi latency** — penting untuk gaming, AR/VR, dan aplikasi real-time.

## 9. Wi-Fi 8 (802.11bn) — Arah Masa Depan

Fokusnya **bukan kecepatan puncak**, melainkan **Ultra High Reliability (UHR)**:

```
Target dibanding Wi-Fi 7:
  +25% throughput pada SNR yang sama
  −25% latency pada persentil ke-95
  −25% kehilangan MPDU
```

**Fitur utama: Multi-AP Coordination**
```
Coordinated Spatial Reuse (Co-SR)  → AP menyesuaikan daya berdasarkan
                                      kedekatan perangkat (+15–25% efisiensi
                                      di area padat)
Coordinated Beamforming            → beberapa AP menyelaraskan arah sinyal
Coordinated OFDMA                  → AP membagi resource unit bersama
```

Mempertahankan dari Wi-Fi 7: band 2,4/5/6 GHz, 4096-QAM, 8 spatial stream, MU-MIMO, OFDMA, kanal sampai 320 MHz.

**Timeline:** chipset ~2026, ratifikasi amandemen ~2028.

## 10. Rate Adaptation dan MCS

**MCS** (*Modulation and Coding Scheme*) menentukan kecepatan berdasarkan modulasi dan coding rate.

```
MCS 0  : BPSK,      coding 1/2  → paling lambat, paling tahan noise
MCS 7  : 64-QAM,    coding 5/6
MCS 9  : 256-QAM,   coding 5/6  (Wi-Fi 5)
MCS 11 : 1024-QAM,  coding 5/6  (Wi-Fi 6)
MCS 13 : 4096-QAM,  coding 5/6  (Wi-Fi 7)
```

**Rate adaptation** terjadi otomatis puluhan kali per detik berdasarkan SNR dan tingkat kegagalan.

```
SNR turun / banyak retransmisi → turunkan MCS (lebih lambat, lebih andal)
SNR naik / transmisi mulus     → naikkan MCS (lebih cepat)
```

⚠️ **Ini alasan kecepatan Wi-Fi berfluktuasi** meski Anda tidak bergerak — kondisi RF berubah terus karena orang lewat, pintu terbuka, dan perangkat lain mengirim.

## 11. Roaming

```
Klien bergerak menjauh dari AP-1 dan mendekati AP-2.

Proses roaming standar (LAMBAT):
1. Klien mendeteksi sinyal AP-1 melemah
2. Scanning kanal lain untuk mencari AP alternatif
3. Autentikasi + asosiasi ke AP-2
4. Autentikasi 802.1X/PSK ULANG (4-way handshake)
5. DHCP (kalau subnet berbeda)
→ 100–500 ms atau lebih → panggilan VoIP putus
```

### Fast roaming: 802.11k/v/r

| Standar | Fungsi |
|---|---|
| **802.11k** | AP memberi klien **daftar AP tetangga** → tidak perlu scan seluruh kanal |
| **802.11v** | AP bisa **menyarankan** klien pindah ke AP lain (BSS Transition Management) |
| **802.11r** | **Fast BSS Transition** — kunci di-cache sehingga tidak perlu 4-way handshake ulang |

Dengan ketiganya, roaming bisa **< 50 ms** — cukup mulus untuk VoIP.

⚠️ **Klien yang menentukan kapan roaming, bukan AP.** AP hanya bisa menyarankan (802.11v) atau memaksa (deauth). Klien dengan algoritma buruk akan **"sticky"** — bertahan di AP jauh dengan sinyal −80 dBm padahal ada AP kuat di dekatnya.

**Mitigasi sticky client:**
```
- Turunkan daya pancar AP agar sel lebih kecil dan batas lebih tegas
- Aktifkan minimum RSSI threshold (AP memutus klien di bawah ambang)
- Matikan rate rendah (klien jauh tidak bisa bertahan)
- Aktifkan 802.11k/v/r
- Perbarui driver klien
```

```
# MikroTik — minimum signal strength
/interface wireless access-list add signal-range=-75..120 authentication=yes
/interface wireless access-list add signal-range=-120..-76 authentication=no
   ← klien dengan sinyal lebih lemah dari −75 dBm ditolak
```

## 13. Ringkasan

- Generasi: **Wi-Fi 4 (11n, MIMO)** → **Wi-Fi 5 (11ac, 80/160 MHz)** → **Wi-Fi 6 (11ax, OFDMA)** → **Wi-Fi 6E (6 GHz)** → **Wi-Fi 7 (11be, MLO)** → Wi-Fi 8 (11bn, keandalan).
- **CSMA/CA** dipakai karena radio tidak bisa mendengar saat mengirim. Setiap frame data **wajib di-ACK** di layer 2.
- **RTS/CTS** memecahkan hidden node tetapi menambah overhead — aktifkan hanya bila perlu.
- **Throughput nyata 40–60% dari PHY rate** karena half duplex, overhead, contention, rate adaptation, dan airtime sharing.
- **Klien lambat memakan airtime tidak proporsional** — pakai airtime fairness dan matikan rate rendah.
- Frame 802.11 punya **hingga 4 alamat MAC**. Management dan control frame **tidak terenkripsi** pada WPA2 → serangan deauth. **802.11w/PMF** memperbaikinya (wajib di WPA3).
- **Hidden SSID tidak memberi keamanan** dan justru membocorkan riwayat jaringan klien.
- **MIMO**: kecepatan dibatasi sisi dengan stream paling sedikit. **OFDMA (Wi-Fi 6)** memberi peningkatan lebih konsisten daripada MU-MIMO.
- **BSS Coloring** mengurangi penundaan tidak perlu antar-sel; **TWT** menghemat baterai IoT.
- **MLO (Wi-Fi 7)** memberi konsistensi latency, bukan sekadar kecepatan puncak.
- **Klien yang menentukan roaming** — atasi sticky client dengan daya lebih rendah, minimum RSSI, dan **802.11k/v/r**.

1. Karena **radio tidak dapat mendengar saat mengirim**. Sinyal yang dipancarkan perangkat itu sendiri jutaan kali lebih kuat daripada sinyal yang datang dari perangkat lain, sehingga penerima "tuli" selama transmisi. Deteksi tabrakan (CD) mustahil dilakukan.
   Solusinya adalah **menghindari** tabrakan sebelum terjadi (CA): dengarkan kanal, tunggu jeda (DIFS), lalu tunggu backoff acak sebelum mengirim. Keberhasilan dikonfirmasi lewat **ACK** — kalau ACK tidak datang, pengirim menyimpulkan terjadi tabrakan dan mengulang dengan contention window yang lebih besar.

2. **Bukan masalah — ini normal dan diharapkan.** Angka 9,6 Gbps adalah PHY rate teoretis maksimum yang hanya tercapai dengan 8 spatial stream, kanal 160 MHz, MCS 11 (1024-QAM), SNR sempurna, dan satu klien.
   Klien nyata (ponsel/laptop) biasanya **2x2:2** dengan kanal 80 MHz — batas teoretisnya sudah turun menjadi ~1,2 Gbps. Setelah dikurangi overhead protokol (~40–50%), contention, dan half duplex, **400–600 Mbps adalah hasil yang baik**.
   Yang perlu diperiksa kalau angkanya jauh lebih rendah: SNR, jumlah spatial stream klien (`iw dev wlan0 link`), lebar kanal yang dipakai, jumlah klien lain di sel, dan apakah uplink AP (kabel/PoE) menjadi bottleneck.

3. **Hidden node** terjadi ketika dua klien dapat mendengar AP tetapi **tidak dapat mendengar satu sama lain** (terhalang dinding atau berada di sisi berlawanan dari AP). Karena keduanya tidak mendeteksi transmisi yang lain, keduanya mengira kanal sepi dan mengirim bersamaan — **tabrakan di AP**, dan kedua frame rusak.
   **Solusi RTS/CTS:** klien mengirim **RTS** ke AP; AP membalas dengan **CTS** yang didengar **semua** klien dalam jangkauannya. Klien lain membaca durasi di CTS dan menetapkan **NAV** — mereka diam selama waktu itu. Dengan begitu klien tersembunyi pun tahu kapan harus menunggu.
   ⚠️ RTS/CTS menambah overhead signifikan, jadi ambangnya (`rts-threshold`) biasanya diset tinggi. Aktifkan hanya kalau retransmisi tinggi dan topologi memang menunjukkan hidden node.

4. **Dampak: throughput seluruh sel bisa turun 50–80%.** Perangkat 802.11b hanya memahami DSSS, bukan OFDM. Agar ia tidak "menabrak" transmisi OFDM yang tidak dapat ia deteksi, AP mengaktifkan **protection mechanism** — setiap transmisi OFDM harus didahului RTS/CTS atau CTS-to-self yang dikirim pada rate rendah (1–11 Mbps). Overhead ini berlaku untuk **semua** klien, termasuk yang Wi-Fi 6.
   Ditambah lagi, perangkat 802.11b sendiri memakan airtime sangat lama untuk data yang sedikit (1 MB pada 1 Mbps = 8 detik).
   **Pencegahan:** matikan rate rendah agar perangkat itu tidak bisa terhubung sama sekali:
   ```
   /interface wireless set wlan1 basic-rates-b="" supported-rates-b="" \
       basic-rates-a/g=12Mbps
   ```
   Di AP enterprise, cari opsi "minimum data rate" atau "legacy rate control" dan set minimal 12 atau 24 Mbps.

5. Ketika SSID disembunyikan, AP tidak menyiarkannya di beacon — sehingga **klien harus aktif mencarinya** dengan mengirim **Probe Request yang berisi nama SSID dalam plaintext**. Perangkat melakukan ini **terus-menerus, di mana pun ia berada**, untuk semua jaringan tersembunyi yang pernah tersimpan.
   Akibatnya: siapa pun yang memantau di kafe, bandara, atau jalan bisa mengetahui **daftar jaringan tersembunyi yang biasa Anda kunjungi** — termasuk nama kantor atau rumah Anda. Ini kebocoran privasi yang nyata dan dapat dipakai untuk pelacakan.
   Sementara itu, keamanan yang "didapat" nol: SSID tersembunyi tetap muncul dalam Probe Response dan Association Request, dan alat seperti `airodump-ng` menemukannya dalam hitungan detik. **Jangan sembunyikan SSID.**

6. **MU-MIMO** memakai **domain ruang** — beberapa spatial stream dikirim ke klien berbeda **pada frekuensi dan waktu yang sama**, dipisahkan lewat beamforming. Efektif untuk **transfer besar** ke beberapa klien, tetapi butuh kondisi RF yang baik, klien yang mendukung, dan channel sounding yang mahal.
   **OFDMA** memakai **domain frekuensi** — kanal dibagi menjadi **Resource Unit (RU)** kecil, dan RU berbeda dialokasikan ke klien berbeda dalam **satu transmisi**. Efektif untuk **banyak paket kecil** dari banyak perangkat (IoT, ponsel, sensor) — persis pola trafik yang paling umum.
   **Perbedaan praktisnya:** MU-MIMO menaikkan kapasitas puncak dalam kondisi ideal; **OFDMA menaikkan efisiensi secara konsisten** di lingkungan padat. Karena itu OFDMA dianggap peningkatan terpenting Wi-Fi 6.

7. Ini masalah **roaming**. Yang diperiksa dan dikonfigurasi:
   (a) **Aktifkan 802.11k/v/r** di semua AP — k memberi daftar tetangga, v menyarankan perpindahan, r menghilangkan kebutuhan 4-way handshake ulang (roaming < 50 ms).
   (b) **Periksa cakupan** — apakah ada area dengan sinyal < −67 dBm? Lakukan site survey; tambahkan AP kalau perlu.
   (c) **Turunkan daya pancar AP** agar sel lebih kecil dan batas antar-sel lebih tegas — sel yang terlalu besar membuat klien bertahan terlalu lama.
   (d) **Aktifkan minimum RSSI threshold** agar AP memutus klien yang sinyalnya terlalu lemah, memaksanya roaming.
   (e) **Matikan rate rendah** sehingga klien jauh tidak bisa bertahan.
   (f) **Pastikan semua AP di subnet/VLAN yang sama** untuk SSID itu — kalau berbeda subnet, klien harus DHCP ulang (kecuali ada mobility tunnel di WLC).
   (g) **Perbarui driver/firmware klien** — banyak masalah sticky client berasal dari algoritma roaming klien yang buruk.
   (h) Aktifkan **WMM/QoS** dan beri prioritas trafik suara.

8. **MLO (Multi-Link Operation)** adalah fitur inti Wi-Fi 7 yang memungkinkan satu klien **terhubung ke beberapa band secara bersamaan** (mis. 5 GHz dan 6 GHz) dalam **satu asosiasi logis** — bukan memilih salah satu seperti generasi sebelumnya.
   **Manfaat utamanya bukan kecepatan puncak, melainkan konsistensi latency dan keandalan:** kalau satu band mengalami interferensi atau congestion sesaat, trafik langsung mengalir lewat band lain **tanpa memutus koneksi** dan tanpa proses roaming. Ini menghilangkan lonjakan latency yang merusak gaming, AR/VR, video call, dan aplikasi real-time.
   Manfaat tambahan: agregasi throughput (kapasitas kedua band dijumlahkan) dan perpindahan band yang mulus tanpa reasosiasi.
